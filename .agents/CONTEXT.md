# Project context

Exphere connects engineering objectives, decisions, agent-assisted work, and verifiable evidence. The current tree retains the private SDK in `packages/sdk` and the separate private CLI in `packages/cli`, which owns `ex` for microruntime descriptors, Terraform, Kubernetes, and explicit consumer hooks. The SDK TypeScript API remains empty. A minimal Next.js website consumes the public-intent design token package; the public-intent web package currently holds only source placeholders and a SmoothUI development dependency. The earlier API and protobuf workspaces remain absent. Root shell adapters now support Biome, workspace build/type checking, scoped contract tests, and local Git hooks; these controls do not implement the broader workflow engine. Institutional adoption and quality contracts remain proposals. The intended CLI distribution and project setup described below are not implemented or evidence of production integration.

- **Intent:** reduce engineering friction by connecting objectives, decisions, agent-assisted work, and verifiable evidence.
- **Boundary:** consumers choose the stack, components, and composition; the platform defines security, observability, testing, resource, and quality contracts with the responsible organizational owners.
- **Adoption:** incremental, starting with a pilot. Workflow profiles and institutional boundaries still need validation with the teams.
- **Workflow:** every adaptation in [Workflows](../.exphere/workflows/README.md) follows the same SDD cycle. Design, operations, SRE, FinOps, and [Dev](../.exphere/workflows/dev/README.md) specialize checks, checkpoints, artifacts, and integrations. They remain documentary drafts without an executor.
- **Development direction:** Exphere is intended to be developed using its own CLI and SDD. The project supplies `.exphere` now so its documented workflows are available while the corresponding CLI setup and workflow commands are still being built. This does not mean that the CLI already executes or enforces every development activity.
- **Installation direction:** installing the Exphere CLI through npm is intended to generate `.exphere` in the consumer project. That generation is future behavior; no installation mechanism is implemented for it. The existing user-local command setup and microruntime commands do not create this workflow directory.
- **Architecture under discussion:** the proposed [microruntime architecture](../.artifacts/design/0005-DD-microruntime-architecture.dd.md) and [detailed requirements](../.artifacts/design/0002-DD-microruntimes.dd.md).
- **Context sources:** the [PRD](../.artifacts/prd/0001-PRD-exphere.prd.md), [domain configuration](../.artifacts/agents/0007-DD-domain-model.dd.md), and the root [AGENTS.md](../AGENTS.md). No standalone glossary is present; use the terminology recorded in these sources without recreating deleted files.

This file contains consumer context. Future distribution must distinguish this context from generic distributed material. Hypotheses, targets, and proposed adoption are not established organizational facts.
