# CLI

The `ex` CLI is implemented in Go with Cobra and distributed by the private `@exphere/ex` package. The separate `@exphere/sdk` package depends on it and forwards the same executable.

## Supported commands

After source installation and the explicit one-time Bash/Zsh setup, use the project-local command directly:

```sh
ex --help
ex version
```

Help lists the command surface; version prints the current CLI version. For contributors, the direct Go entrypoint is also available:

```sh
go -C packages/ex run ./src/cmd/ex --help
```

## Configuration and local lifecycle

The CLI implements project initialization, prerequisite diagnostics, manual/guided runtime configuration, descriptor v2 validation, project-owned kind cluster commands, and bounded Terraform/Kubernetes lifecycle operations. It can also generate editable TypeScript LangGraph source for a finite Job without model calls.

It detects missing tools instead of installing them and loads consumer-built images instead of building them. Application and agent source stays outside runtime units. **Live cluster, Terraform, Kubernetes, and LangGraph Job execution remain operationally unverified.** There is no implemented financial ledger, RAG, or MCP integration.

Source installation requires an existing Go toolchain. It never changes shell profiles automatically. Follow the package reference below for the explicit one-time shell setup; without setup, use `./node_modules/.bin/ex`.

The homepage displays `npx exphere init` as product-facing preview text. It does not establish npm publication or a working initializer.

## Historical contracts

The former shell implementation and runtime hooks are retired. Surviving schemas, source-contract fixtures, and design documents record earlier work; they do not prove feature parity or a deployed integration.

Read the [package-owned CLI reference](https://github.com/jonatassales/exphere/blob/main/packages/ex/README.md) for build commands and exact behavior. Use [Concepts](/docs/concepts#microruntimes-compose-around-existing-applications) to understand the intended microruntime boundary.
